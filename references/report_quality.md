# Report Quality Rules

The report should feel like an ecommerce operating diagnosis, not a generic analytics dashboard.

## Visual Direction

- Use a restrained blue-white report system with strong hierarchy.
- Make the first screen a compact Dashboard overview.
- Use real VOC metrics: review count, Q&A count, sample count, opportunity count, evidence structure, keyword cloud.
- Keep the decision chain visible: 评价洞察 -> 问大家顾虑 -> 经营机会 -> 主图动作 -> 详情页动作 -> 客服FAQ -> 产品改进路线图.

## Layout Rules

- Do not use decorative blocks that do not explain the data.
- Fill large dark areas with useful report content: priority actions, sample coverage, or decision chain.
- Keep keyword cloud based on source text, not only AI-labeled business clusters.
- Keep TOP lists sorted by the label shown in the UI.
- Use tables for comparison and evidence, not for every block.

## Evidence Rules

- Every recommendation must be traceable to reviews, Q&A, or stated missing data.
- If one review can trigger multiple topics, avoid presenting topic hits as unique user counts unless deduplicated.
- Do not let one displayed evidence count exceed its relevant denominator.
- Use neutral themes when category confidence is weak.
